## 設計上の判断（SPEC に無かった点）
| 項目 | 判断 | 理由 |
|---|---|---|
| `online` を出すタイミング | Transport は認証・VER 後に `syncing` を出し、`online` は SyncEngine の初期同期完了後に controller が出す | §10-1「online 前に完了させる」 |
| 再接続後 | Transport が再び `syncing` を出したら controller が再同期して `online` | 切断中に本体側で変わった値を取りこぼさない |
| 書込み専用トリガ（メモリー呼出し・診断の任意書込み） | `controller.trigger()`＝楽観更新しない | 応答値が無いアドレスを楽観更新すると 1.5s 後に必ずロールバック通知が出る |
| 多バイト書込みの coalesce | `bytes.length >= 2` の書込みは同アドレスの未送信分を最新値で上書き | T バー・レベル・名前はすべて多バイト。1 バイト値（ON/OFF・PGM）は順序を保つ |
| LOW（読出し）の送信 | 同一ティック内の連続 `read()` を 1 バッチにまとめるため常に遅延送信 | §3-6「4 件ずつ」をバーストでも守る |
| 読出し範囲の統合 | 隣接・重複する範囲だけ 1 つの RQH にまとめる（`mergeRanges`）。離れた範囲は跨がない | ガイド未記載のアドレスを読まない |
| 認証中の切断 | パスワード送信後に本体が切れば `AUTH_FAILED`、送信前なら `NO_RESPONSE` | モックは誤 PW で切断する（本体の実挙動は §13 で確認） |
| `ERR:n` の扱い | `err` イベント → SyncEngine が最も古い pending をロールバック | ERR はアドレスを伴わないため |
| 受信範囲と pending | 受信した範囲に先頭が含まれる pending は確定扱い（本体の値が正） | 自発通知は 1 バイト単発、RQH 応答は範囲 |

## 依存の追加
- `react-native-tcp-socket` 6.4.3（`npx expo install`）。**React Native Directory では New Architecture「未検証」**（ネイティブ実装は `RCTEventEmitter` ＋ `RCT_EXPORT_MODULE()` の旧ブリッジ形式）。RN 0.86 の TurboModule interop で動く見込み【推測】。`expo.doctor.reactNativeDirectoryCheck.exclude` に入れて doctor を通した。**Mac の Development Build で接続できなければ**、M4 の Swift モジュールに `NWConnection` ベースの TCP を追加して `socket.ts` の実装を差し替える（抽象化済みなので LanTransport は無変更）。
- `tsx`（devDependency）：`npm run mock` 用。
- `@types/node` は既に依存に含まれていたため tsconfig の `types` に `node` を追加（`tools/` と結合テストで `net` を使う）。
