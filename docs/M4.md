## Mac での確認手順（M4 の完了条件）
1. `npm install` → `npx expo prebuild --platform ios --clean` → `cd ios && pod install`（`CrosspointMidi` pod が入ることを確認）
2. Xcode でビルドが通ること（Swift の API は iOS 14+ の UMP 系。`deploymentTarget 17.0`）。コンパイルエラーが出たら `MidiEngine.swift` の該当行を SPEC §7-2 の規則どおりに直す（規則は `core/codec/ump.ts` と同一で、そちらは単体テスト済み）
3. 実機で起動 → S0「USB」タブ → 任意の USB-MIDI 機器を繋いで端点が列挙されること。「その他 → 診断」のログに `driverOwner` の生値が出る（§13：USB は `…USBDriver` か）
4. S0「Bluetooth」タブ →「Bluetooth MIDI デバイスを追加」で `CABTMIDICentralViewController` が出ること（§6-2）
5. ループバック：MIDI 機器を介さず確認するなら、Mac の「Audio MIDI 設定」で IAC/ネットワーク MIDI セッションを作り iPhone から接続、Mac 側で SysEx を受信・返送して往復ログを確認
6. 結果を `docs/VERIFY.md` に記録（端点名、driverOwner、版応答の形式、BLE 復帰時の挙動）

## 設計上の判断（SPEC に無かった点）
| 項目 | 判断 | 理由 |
|---|---|---|
| 接続確認の RQ1 | **全対応機種分の RQ1 版読出しを送る**（V-160HD 用 5byte modelId と V-80HD 用 3byte modelId） | 機種が未確定なので正しい modelId が分からない。本体は自分の modelId 以外には無応答（§4-1） |
| 版の表示 | 6byte が印字可能 ASCII なら文字列、そうでなければ 16 進 | 形式は【不明】（§4-3）。生値はログにも残す |
| 端点消失後 | `reconnecting` のまま 60 秒は再出現を待ち、同 UniqueID が online になったら自動で open → 版確認 → `syncing`。超えたら `error LINK_LOST` | §5-3 / §6-4 |
| BLE の送信間隔 | CommandQueue は USB/BLE とも HIGH 20ms（§4-1 の下限）。連続値の間引き（BLE 50ms）は UI 側の送信頻度で担保 | 20ms 下限はネイティブ側（`MidiEngine.minSendIntervalSec`）でも二重に保証 |
| 経路の判別 | `driverOwner` に "usb" / "ble" or "bluetooth" / "rtp" or "network" を含むかで判定。判別不能は `other`（USB タブには usb+other、BLE タブには ble+other を表示） | §5-2【推測】。生値をイベントで返し §13 で確認 |
| 保存済み端点の再選択 | UniqueID 一致（online）→ 無ければ名前の部分一致 | §5-2 |
| `presentBluetoothPicker` | `UINavigationController` ＋「完了」ボタン。スワイプで閉じた場合も `presentationControllerDidDismiss` で resolve | §7-2 |
| ネイティブ無し環境 | `getCrosspointMidi()` が null → S0 に「この環境では USB / Bluetooth MIDI を使えません」 | jest・Expo Go・シミュレータ（CoreMIDI は動くが端点が無い） |

## 残課題
- `UIBackgroundModes` は設定しない（SPEC §16）。アプリ切替で BLE が切れる挙動は §13 で確認
- `react-native-tcp-socket` が New Architecture で動かなかった場合、この Swift モジュールに `NWConnection` ベースの TCP を追加する（`docs/M2-M3.md` 参照）
